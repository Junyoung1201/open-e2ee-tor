open-e2ee-share-tor 위협 모델 (구현 기준)
========================================

전제
----
사용자는 검증한 o2ee 바이너리를 자기 기기에서 실행함. 서버(o2ee-server)와
네트워크는 믿지 않음. 서버도 클라이언트를 믿지 않음. 독립 보안 감사를 받지 않았음.


구성 요소와 암호
----------------
  전송 계층   Tor onion v3. onion 주소 = 서버 공개키라 Tor가 서버를 인증함.
              주소는 릴리스 빌드에 고정(O2EE_SERVER_ONION). TLS 없음.
  로그인      OPAQUE(opaque-ke 4.0.1, ristretto255, TripleDH, Argon2id KSF).
              식별자에 계정 ID와 서버 onion 주소를 묶음. 비밀번호는 서버로 가지 않음.
              세션 토큰 = HKDF(OPAQUE session key). 서버가 보내지 않으므로 로그인을
              실제로 끝낸 클라이언트만 앎. OPAQUE는 상호 인증이라, 이 계정의 등록
              기록이 없는 서버는 로그인을 완료시킬 수 없음.
  계정 키     기기에서 생성: Ed25519(서명) + age X25519(수신). 개인키는 기기에만,
              비밀번호(age scrypt)로 암호화. 서버에는 자기서명된 공개키 묶음만
              (계정 ID·서버 주소·두 공개키를 서명으로 묶음).
  지문        SHA-256(공개키 두 개) 앞 128비트, XXXX-XXXX-... 8묶음.
  파일        age(X25519, ChaCha20-Poly1305 STREAM)로 수신자에게 암호화.
              안쪽 헤더(전송 ID·보낸 사람·받는 사람·서버·파일명·크기·SHA-256)를
              보낸 사람 Ed25519로 서명. 평문은 1 MiB 단위로 0 패딩.
  가입 남용   서버 발급 HMAC 챌린지 + SHA-256 작업증명(계정 ID에 묶임, 1회용),
              대기 신청 50건 상한, 7일 후 자동 삭제, 관리자 승인.


상호 검증
---------
클라이언트가 서버를 검증
  - onion 주소 고정 + OPAQUE 상호 인증.
  - 상대 공개키: 묶음 서명·계정 ID·서버 주소 검증 후, 처음 보면 지문 확인을
    요구(TOFU)하고 고정. 이후 다른 키면 송수신 모두 거부.
  - 받은 파일: age 인증(변조·잘림 검출) → 헤더 서명(고정된 보낸 사람 키) →
    전송 ID·받는 사람·서버 일치(재전송·다른 수신자 전달 차단) → 내용 SHA-256 →
    패딩이 0이고 그 뒤에 아무것도 없는지. 전부 통과해야 숨김 임시 파일이 최종
    이름을 얻음(덮어쓰지 않음, "이름 (1)").
  - 서버 응답은 크기 상한 후 파싱. 서버 문자열은 제어문자·ANSI·방향 문자 제거.
  - 파일명: 경로 구분자·제어문자·예약 이름 제거, 앞의 점 제거. zip은 자동으로
    풀지 않음.
서버가 클라이언트를 검증
  - 모든 본문 크기 상한, 알 수 없는 필드 거부, 계정 ID는 정규형만 허용.
  - 가입: 작업증명, 묶음 서명과 계정·서버 바인딩 검증.
  - 로그인 시도는 시작(login/start) 단계에서 셈: 비밀번호 추측 1회 = 시작 1회.
    연속 5회 이후 30초부터 두 배씩 최대 15분 잠금. 성공 시 초기화.
    없는 계정도 실제 계정과 구별되지 않는 응답(OPAQUE 가짜 기록).
  - 요청마다 세션·계정 상태(정지 즉시 차단) 확인.
  - 전송 ID는 32자리 소문자 hex만(경로 조작 불가). 업로드는 업로드 키·순서·
    선언 크기 엄수, 실패한 요청의 일부 바이트는 잘라냄. 다운로드·삭제는 받는
    사람만. 받는 계정별 대기 용량 상한, 디스크 여유 1 GiB 유지.
  - "공식 클라이언트만" 접속하게 하는 것은 원리상 불가능함(역공학으로 흉내 가능).
    대신 어떤 클라이언트도 위 검사를 통과하지 않으면 아무것도 할 수 없음.


방어하는 것
-----------
  - 서버 장악·디스크 압수: 파일 내용, 파일명, 정확한 크기, 보낸 사람, 개인키,
    비밀번호 원문이 서버에 없음.
  - 서버의 키 바꿔치기(중간자): 지문 확인 후에는 차단. 서버가 남의 묶음을 넘기면
    서명·계정 바인딩에서 실패.
  - 서버의 변조·위조·재전송·다른 사람에게 전달: 위 검증 단계에서 거부, 파일 미저장.
  - 네트워크 관찰, 서버 위치 추적: Tor. 서버는 클라이언트 IP를 알 수 없음.
  - 미승인 사용, 가입 폭주: 관리자 승인, 작업증명, 대기 상한.
  - 온라인 비밀번호 추측: 계정별 백오프.
  - 관리자 페이지 원격 접근: 127.0.0.1 전용(비루프백 바인드는 시작 거부),
    torrc에 매핑하지 않음, Host 허용 목록(DNS 리바인딩), Origin·Sec-Fetch-Site·
    CSRF 토큰, Argon2id 비밀번호와 실패 백오프, HttpOnly·SameSite=Strict 쿠키,
    스크립트 없는 HTML + 엄격한 CSP, 출력 이스케이프.
  - 사후 로그 분석: 서버·Tor 모두 로그를 남기지 않음(아래 노로그).
  - 에이전트 메모리: 같은 사용자의 다른 프로세스가 ptrace·/proc으로 읽지 못하게
    dumpable 해제, 코어 덤프 금지. 소켓은 0600 + 접속자 UID 확인.


방어하지 못하는 것 / 한계
-------------------------
  - 지문 확인을 대충 넘긴 첫 연락: 그 순간 서버가 준 키를 믿게 됨(TOFU).
  - 서버 장악 + opaque_setup.bin 유출: 약한 비밀번호는 오프라인 대입 가능.
    단, 개인키는 기기에만 있으므로 비밀번호만으로 파일을 열 수는 없음.
    클라이언트는 10자 미만·쉬운 비밀번호를 거부함.
  - 메타데이터: 계정 목록·공개키, 대기 전송의 받는 사람, 1 MiB 단위 크기,
    실시간 접속·전송 시각(저장하지 않을 뿐 서버는 볼 수 있음).
  - 서비스 거부(서버 운영자, Tor 네트워크, 한 수신자의 대기 용량 채우기 등).
    Tor PoW·intro 제한·용량 한도는 완화책일 뿐임.
  - 사용자 기기 감염, root, 같은 사용자 권한의 악성 프로세스(에이전트에 요청을
    보낼 수 있음), 스왑에 남은 메모리.
  - 릴리스 서명 키 유출, 바이너리를 처음 받는 경로 오염.
  - 받은 파일 자체의 악성 여부(검사하지 않음, 실행하지 않음).
  - 삭제는 일반 파일 삭제. SSD·스냅샷·백업의 물리 소거 보장 없음
    (서버에 남는 것은 암호문뿐).
  - 의존성 경고: rsa 크레이트 타이밍 취약점(RUSTSEC-2023-0071)이 Arti 키 저장소
    경유로 포함됨. Tor 클라이언트는 RSA 개인키 연산을 하지 않아 영향 없다고 판단,
    deny.toml에 사유와 함께 예외 처리.


설치 안내와 업데이트
--------------------
  /guide        onion으로 제공하는 영문 설치 안내(어두운 테마, HTML+CSS만, 스크립트 없음).
                페이지와 파일이 같은 서버에서 오므로, 페이지만으로는 아무것도 증명하지
                못함을 명시하고 릴리스 공개키를 관리자에게 따로 받아 대조하도록 안내.
  /download/*   게시된 릴리스 목록에 있는 파일과 그 서명만 제공.
  o2ee update   수동 실행만(자동 확인 없음). 바이너리에 박힌 릴리스 공개키(minisign,
                O2EE_RELEASE_PUBKEY)로 매니페스트 서명을 확인하고, 이 서버의 onion
                주소·이 플랫폼·현재보다 높은 버전·서명된 크기와 SHA-256이 모두 맞을 때만
                실행 파일을 원자적으로 교체. 실패하면 기존 파일 그대로. 서명 키는 오프라인에만.
  방어          장악된 서버가 가짜 업데이트를 설치시키거나 옛 버전으로 되돌리는 것.
  한계          서버는 업데이트를 숨길(보류할) 수 있음. 처음 받는 바이너리와 릴리스
                공개키는 다른 경로의 확인에 달려 있음. 릴리스 키 유출 시 위조 가능.


노로그
------
  서버   접근 로그·요청 단위 출력 없음. systemd StandardOutput/Error=null.
         로그인 이력·마지막 접속 시각 저장 안 함. 보낸 사람을 저장하지 않음.
         시각은 시간 단위 반올림(가입 시각, 전송 만료). 세션·로그인 상태·실패
         횟수·관리자 세션은 메모리에만. 거절된 신청, 받은 전송, 만료 전송은 즉시
         삭제. 데이터 폴더에는 state.json, opaque_setup.bin, admin_password,
         files/만 있음(테스트로 확인).
  Tor    사용자 인스턴스, Log err stderr → null, SafeLogging 1, SocksPort 0.
  기타   LimitCORE=0. 클라이언트도 로그 파일을 만들지 않음.
